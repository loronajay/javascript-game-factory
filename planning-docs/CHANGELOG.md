## Factory Launcher — Custom Domain + Progress-Sync Repair (2026-07-27)

**The site moved to `factory.jayarcade.com`.** The apex `jayarcade.com` belongs to the separate `loronajay/games-directory` repo (Jay's Retro Arcade and the Cabinet OS the Pi kiosks pull from) and must not be reassigned — GitHub allows one repo per domain. A subdomain avoids that entirely: one Namecheap CNAME (`factory` → `loronajay.github.io`), a `CNAME` file at the repo root, Enforce HTTPS on (Let's Encrypt cert issued 2026-07-28 01:18 UTC). The custom domain serves the repo at the **root**, not under `/javascript-game-factory/`; all in-site paths are relative so nothing broke, and GitHub redirects the old Pages URLs. `APP_BASE_URL` on Railway and the CORS allow-list in `platform-api/src/http-utils.mts` both moved with it (the old Pages origin stays allow-listed for old links). The privacy page's contact became `leojaylorona@gmail.com` — no mailbox exists on the domain.

Two operational gotchas found the hard way: saving the custom domain in Settings → Pages makes GitHub commit a `CNAME` straight to `main`, so the next local `git push` is rejected until you `git pull --rebase` (never force-push it — that unsets the domain); and Railway's GitHub connection had silently broken ("GitHub Repo not found"), so backend pushes were deploying nothing. Auto-deploy from `main` with root directory `platform-api` is reconnected.

**Progress sync: signed-in accounts could end up with progress the server never had.** The one-time local-ownership migration (`migration:local-ownership-v1`) could be *consumed without granting anything* — a fresh device (a new packaged-app install signing into an existing account) posted an empty backfill, which burned the one-shot for the whole account. The device that actually held the progress could then never migrate it, so the server owned nothing and every other surface correctly showed zero. Fixed in three places: an empty backfill is inert server-side, the client no longer posts one, and accounts already stranded self-heal while the server owns nothing for them. Verified end-to-end on a real device — units, skins, Valor, tutorials, and campaign clears all landed on the Android build from the server. Trust model and the follow-up to close the widened window: `games/tactical-arena/SECURITY.md`.

Debugging note worth keeping: Chromium batches localStorage writes into leveldb, so `adb`-pulled dumps of the packaged app are stale unless you `am force-stop` the app first. Several dumps during this investigation looked like the sync had never run when it had.

## Factory Launcher — Security Hardening (2026-07)

A hardening pass closed the money-critical holes. Backend (`platform-api/`): the public game-progress `/claims` route now rejects `premium-*` kinds (premium entitlements are Stripe-fulfillment-only); CORS is restricted to an allow-list (`https://loronajay.github.io` + localhost, extendable via `ALLOWED_ORIGINS`) instead of reflecting any origin with credentials; `/activity` requires auth and stamps the server-verified actor; JWT verification is pinned to HS256; per-IP rate limiting guards auth + Stripe checkout-session creation; uploads are validated by magic bytes (not the client MIME), which also guards the Cloudinary `raw` audio store. Tactical Arena's economy is now server-authoritative for signed-in players — Valor is spent through a server endpoint (atomic deduct+grant), and ownership is reconciled down to the server's set on boot (injected local ownership is dropped and self-heals) with a one-time backfill so no existing progress is lost. Full model + invariants in `games/tactical-arena/SECURITY.md`.

## Factory Launcher — Top Ladder Rankings (2026-07-25)

The "Top Ladder Rankings" panel on `/me` and `/player` had a normalize contract and a renderer but nothing behind it — both pages passed `ladderPlacements: []` forever. It now shows real cross-game standings.

The data was already there and already game-agnostic: `game_ratings (player_id, game_slug, rating, wins, losses, draws)` is written by `POST /ratings/:slug` (no slug allowlist) and by the ranked match reporter. What was missing was a platform-level read — the only leaderboard query lived inside the auth-gated `/ranked` family and folded in Tactical Arena's ranked cosmetics.

**The plug-in point is `platform-api/src/services/ladder-catalog.mts`.** Adding a game's ladder is one entry (`gameSlug`, `title`, `cabinetSlug`, `source`, `unitLabel`, `minMatches`) — the placement query, the public board route, `GET /ladders`, and both profile panels all read the registry, so which games rank is a data question, never a code question. The rating slug is deliberately separate from the cabinet slug: Sumorai stores ranked play under `sumorai-ranked` so casual matches never touch the ladder, and `title` lives in the registry because such a slug has no catalog entry to derive a name from. Registered today: `tactical-arena`, `sumorai-ranked`.

`db/ladders.mts` holds the two reads. `getPlayerLadderPlacements` ranks a player across every registered ladder in one query (window `rank()` per `game_slug`, joined against an `unnest` of the registry's slugs and per-ladder placement thresholds) and returns rank, field size, rating, and record. `getLadderStandings` is the public top-N board for one ladder. Both share one ordering — rating desc, win differential, then `player_id` — which makes the order total, so a board row and that player's profile placement can never disagree. Migration `025` adds the matching `game_ratings (game_slug, rating desc, …)` index; the primary key is `(player_id, game_slug)` and would have sorted the whole table per request.

`routes/ladder-routes.mts` serves `GET /ladders`, `GET /ladders/:gameSlug`, and `GET /players/:playerId/ladders`, all public — standings are public information, and the auth gate on `/ranked` exists because those routes also queue and report matches. The handler is dispatched **before** the `/players` family so the `ladders` suffix is not swallowed; a route-order test pins that, since a regression there would silently empty the rail rather than error.

Client-side, placements are fetched live (`fetchPlayerLadderPlacements`) by `me-page/page-data` and `player-page/loader`, never cached: a standing moves whenever anyone *else* on that ladder finishes a match, so a stored copy is stale by definition. `buildRankingItems` prefers live placements over whatever sits on the profile record and renders a fuller line — `1284 ELO` over `Rank #3 of 42 · 12W-4L-1D` — trimming to just `Rank #N` when a source carries nothing more. Empty states now say a placement has to be earned instead of promising standings are "coming online".

Still open: badges keyed off placement (`planning-docs/badge-plans/…` defers these pending ranked seasons and placement history), and a public board page — `GET /ladders/:slug` has no UI outside Tactical Arena's own in-game modal yet.

## Factory Launcher — Comment Moderation (2026-07-25)

Players can now delete comments on their own posts and photos, so moderation of a thread doesn't require deleting the whole post. The rule is the same on both surfaces: a comment can be removed by **its author** or by **the author of the post / owner of the photo**.

Backend owns the decision. `deleteThoughtComment` (`db/thoughts.mts`) and `deletePhotoComment` (`db/photos.mts`) load the comment and its parent inside a transaction, check the requester against both stored owner ids, delete, then recount and write back `comment_count`; they return `{ ok, reason }` so the routes can map `forbidden` → 403 and `not_found` → 404. `DELETE /thoughts/:id/comments/:commentId` and `DELETE /photos/:id/comments/:commentId` take the requester from the **verified session** (`authClaims.playerId`), never from the request body — `handleThoughtRoute` now receives `authClaims` for this reason (it previously took none).

**Every thought mutation is now account-holders-only, with the actor taken from the verified session.** `POST /thoughts`, `/thoughts/:id/comments`, `/shares`, and `/reactions` previously had no auth at all and read the actor from the request body — so any caller could post, comment, share, or react *as anyone*. All four now require a session and derive the actor from it; `POST /thoughts` also overwrites any body-supplied `authorPlayerId`. The photo comment/reaction routes already required a session but still read `actorPlayerId` from the body, letting any signed-in user act as another player; they now use the session id too.

The frontend had to follow, because `/thoughts` and `/player` are public-read pages whose social actions gated on the *local factory profile* — which every guest has. Both pages now resolve the auth session at boot and treat guests as read-only (`/me` already redirects to sign-in, so it was unaffected). Reading stayed public on purpose: opening a comment thread no longer requires a profile, and the sheet renders the thread for everyone but swaps the reply form for a "Sign in to join the conversation." prompt when signed out — the same shape the photo viewer already used for its comment form.

`DELETE /thoughts/:id` gained authorization in the same pass. It previously took an id and deleted, with no auth check at all — any caller who could reach the API could delete anyone's post. It now requires a verified session and only lets the post's author delete it. `deleteThought(db, thoughtId, requesterPlayerId)` carries the ownership check inside the delete statement (`where id = $1 and author_player_id = $2 returning id`) rather than doing a read-then-delete, so concurrent requests cannot race past it; when nothing is deleted it does a follow-up existence check purely to answer 404 vs 403. The response body is unchanged (`{ deleted, id }`), and the local-first client ignores the API result before deleting from its own cache, so guest posts (local-only, never persisted) still delete normally.

Deleting social content now also clears the notifications that announced it. Notifications embed a snapshot of what they reference, so a removed comment/post/photo used to leave a notification pointing at nothing. `deleteNotificationsByPayloadRef` (`db/notifications.mts`) deletes by `payload->>'<key>'`, with the key allowlisted to `commentId`/`thoughtId`/`photoId` since it is interpolated into a jsonb lookup; it swallows its own errors so cleanup can never fail the content deletion. Wired into four routes: comment delete (both surfaces) clears by `commentId`, post delete clears by `thoughtId`, photo delete clears by `photoId` — the last two only when the delete reports something was actually removed. No client change was needed: the notification badge and list refresh on page load and on each dropdown open, so a cleared notification simply stops appearing.

Frontend mirrors the rule only to decide whether the control is worth showing. `renderCommentSheet` reads `commentPanelState.viewerPlayerId` plus the new `commentTargetAuthorPlayerId` card field (for a repost, the *original* author — moderation follows the thread, not the card) and `buildCommentListHtml` reads `viewerPlayerId`/`isPhotoOwner`. The photo viewer gained `isPhotoOwner` alongside the existing `isOwner`: `isOwner` gates that surface's own "Remove Photo" button, `isPhotoOwner` is the identity fact, which is what the profile-embedded viewer needed (it offers comment moderation but not photo removal). Local-first `deleteThoughtCommentPost` mirrors the same rule for guests; `deleteThoughtCommentWithApi` only touches the local cache after the server confirms.

## Factory Launcher — Layout Editor UX Rebuild (2026-07-25)

`/me/layout` was rebuilt as a proper editor frame instead of a document page. The workspace is now full-bleed (it no longer inherits the shared 1120px `.arcade-shell` column) and locked to the viewport height as three independently-scrolling columns: panel rail, canvas viewport, inspector rail. The inspector moved out of the left sidebar — previously it sat *below* ~50 panel rows, so selecting anything pushed its own controls off-screen.

The left rail's flat dump of panels + composition elements became a grouped, searchable tree: `js/profile-layout/layout-panel-list.mts` (new module, extracted out of `layout-inspector-view.mts`) owns the pure grouping/filter model plus its markup. Rows group by profile section with a visible `enabled/total` count, groups auto-collapse when unused and auto-open on selection, labels wrap to two lines instead of truncating to `He…`, and each row carries an inline eye toggle so show/hide no longer needs a select → scroll → checkbox round-trip. The old per-row `HIDDEN`/`IDENTITY`/`ABOUT` badges — which were what squeezed the labels — are gone; state reads from row styling and the eye icon.

Canvas zoom was reworked around an explicit scroll stage (`buildZoomFrame` returns `stageWidth`/`stageHeight` instead of mutating the wrap's height/overflow), so zooming out shrinks the scroll area instead of leaving a tall empty gutter, and `MAX_ZOOM` was raised from `1` to `2` for fine composition-element work. Fit still never magnifies past 100%.
